# Prism

Веб-мессенджер: чат в реальном времени, отправка медиа (картинки/файлы), статусы "в сети" / "не в сети" и индикатор набора текста.

## Стек

- **Backend:** Java 11+, Spring Boot 2.7 (Web, WebSocket/STOMP, Security, Data JPA), JWT (jjwt)
- **База данных:** H2 (файловая, работает из коробки, без установки) с опциональным переключением на PostgreSQL
- **Frontend:** обычный HTML/CSS/JS (без сборки), SockJS + StompJS с CDN — отдаётся тем же Spring Boot приложением как статика
- **Реальное время:** WebSocket по протоколу STOMP, персональные очереди `/user/queue/messages` и `/user/queue/typing`, канал присутствия `/topic/presence`

## Возможности

- Регистрация и вход (JWT, пароли хранятся как BCrypt-хэши), тёмная неоновая тема на странице входа и в приложении
- Личные чаты 1-на-1 с историей сообщений
- Групповые чаты и публичные каналы (создание, вступление, рассылка сообщений через WebSocket)
- Отправка изображений и файлов (индикатор загрузки, превью картинок в чате)
- Отправка файлов с кодом (в т.ч. `.java`), включая автоконвертацию вставленного через копипаст кода — с подсветкой синтаксиса прямо в сообщении
- Голосовые сообщения (запись через MediaRecorder, воспроизведение прямо в чате)
- Всплывающая модалка с расширенным набором эмодзи для отправки в переписке
- Личный кабинет: изменение имени, статуса и фото профиля с фоторедактором (обрезка/масштаб) перед загрузкой (`GET/PUT /api/users/me`, `POST /api/users/me/avatar`)
- Бейджи непрочитанных сообщений в списке контактов, групп и каналов; статус "Просмотрено" под своими сообщениями в личных чатах
- Общая доска расписаний и объявлений, видимая всем пользователям (`GET/POST /api/board`, `DELETE /api/board/{id}`)
- Статус "в сети / не в сети" с временем последнего визита
- Индикатор "печатает…"

## Требования

- JDK 11 или новее
- Maven 3.6+
- Интернет-доступ при первой сборке (Maven скачает зависимости из Maven Central)

## Запуск

```bash
cd messenger
mvn spring-boot:run
```

Приложение поднимется на `http://localhost:8081` — интерфейс уже открыт по этому адресу (статика раздаётся из `src/main/resources/static`).

База данных по умолчанию — файловая H2 (`./data/messenger.mv.db`), создаётся автоматически при первом запуске. Загруженные файлы сохраняются в `./uploads`.

### Переключение на PostgreSQL (опционально)

```bash
docker compose up -d
mvn spring-boot:run -Dspring-boot.run.profiles=postgres
```

## Как это работает вкратце

1. **Аутентификация** — `POST /api/auth/register` и `/api/auth/login` возвращают JWT. Токен кладётся в `localStorage` и используется как `Authorization: Bearer <token>` для REST-запросов и как STOMP CONNECT-заголовок для WebSocket.
2. **Список контактов** — `GET /api/users/contacts` возвращает всех зарегистрированных пользователей, кроме текущего, с их онлайн-статусом.
3. **История чата** — `GET /api/messages/{username}` отдаёт переписку с конкретным пользователем.
4. **Отправка сообщения** — клиент публикует в `/app/chat.send`, сервер сохраняет сообщение в БД и рассылает его в приватные очереди отправителя и получателя (`/user/queue/messages`), поэтому оба видят сообщение сразу.
5. **Медиа** — файл сначала загружается через `POST /api/media/upload` (multipart), сервер возвращает URL (`/media/<uuid>`), затем клиент отправляет обычное чат-сообщение с этим URL через STOMP.
6. **Статусы онлайн** — при подключении/отключении WebSocket-сессии сервер обновляет счётчик активных сессий пользователя и рассылает изменение в `/topic/presence`.
7. **"Печатает…"** — клиент публикует события в `/app/chat.typing`, сервер пересылает их только адресату в `/user/queue/typing`.

## Известные ограничения (что стоит доработать перед продакшеном)

- Список контактов — это все пользователи системы; нет отдельного механизма "добавить в друзья"
- Нет группы/каналы — только личные чаты 1-на-1
- Нет пагинации истории сообщений (при очень долгой переписке стоит добавить)
- Секрет JWT лежит в `application.yml` открытым текстом — для продакшена вынести в переменные окружения/секреты
- Загруженные файлы хранятся на диске сервера без вирусной проверки — для продакшена стоит добавить сканирование и ограничение типов файлов
